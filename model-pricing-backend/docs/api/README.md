# 接口通用约定（前端对接必读）

> 本文件是**前端与后端的唯一契约源头**。各模块接口详见同目录下按阶段编号的文件
> （如 `04-models.md` = 阶段 4 模型管理 M1）。
> 后端实现以本目录为准；`openapi/swagger.json` 由代码注解自动生成，属**产物**而非源头。

---

## 1. 基础路径与三门户

| 门户 | 前缀 | 使用者 |
|---|---|---|
| 内部 | `/api/internal/*` | 运营 / 采购 / 定价 / 销售 / 财务 / 管理员 |
| 供应商 | `/api/supplier/*` | 供应商操作员 |
| 客户 | `/api/customer/*` | 客户操作员（浏览器 + H5/小程序共用） |

- **账号按门户隔离**：内部账号无法登录供应商/客户门户，反之亦然。
- 路由前缀决定 `portal_type`，**请求体里不需要也不应该传门户类型**。

## 2. 鉴权

```
Authorization: Bearer <token>
```

- `token` 由 `POST /api/{portal}/auth/login` 返回，**12 小时有效，滑动续期**。
- 前端只需存 token 并在每次请求带上；权限包（菜单、数据域、字段剔除）由服务端在登录时下发快照。
- 前端按权限包隐藏菜单**仅为体验**，服务端会重做全部校验，绕过前端隐藏是无效的。

## 3. 统一响应包

所有接口（含错误）一律返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "requestId": "b292a7a0-b2b8-4ced-a4f3-8612f30c42de"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` = 成功；非 0 = 业务错误（见第 7 节错误码表） |
| `message` | string | 成功固定 `"ok"`；失败为可直接展示给用户的中文提示 |
| `data` | any | 业务载荷；失败时固定为 `null` |
| `requestId` | string | **本次请求**的追踪号，与响应头 `X-Request-Id` 一致 |

**前端判定逻辑**：先看 HTTP 状态码，再看 `code`。`code != 0` 时**不要**读 `data`。
排查问题时把 `requestId` 发给后端，可精确定位日志。

## 4. 分页

列表接口统一使用：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | ≥ 1 |
| `size` | int | 20 | 1~100 |

响应 `data` 统一结构：

```json
{ "list": [], "total": 137, "page": 1, "size": 20 }
```

H5/小程序下拉加载可用游标模式 `?cursor=&size=`，返回体相同（`cursor` 为空表示首页）。

## 5. 时间与金额

| 类型 | 格式 | 示例 |
|---|---|---|
| 时间 | **ISO 8601 带时区** | `2026-09-08T15:04:05+08:00` |
| 日期 | `YYYY-MM-DD` | `2026-09-08` |
| 金额 | **字符串** | `"0.00001234"` |

> 金额必须用字符串：JSON number 会丢精度（0.1 + 0.2 问题），单价、成本、毛利一律字符串传输。
> 前端做展示时再自行转数值，**不要**用 JS number 做金额运算。

## 6. 幂等

会产生**业务新版本**或**资金/合同影响**的写操作必须带请求头：

```
Idempotency-Key: <客户端生成的唯一串，建议 UUID>
```

已实现的行为（后端 `idempotency_key` 表）：

| 情况 | 结果 |
|---|---|
| 首次请求 | 正常执行，记录结果 |
| 同 key + 相同请求体重放 | **不重复执行业务**，直接返回首次结果（响应体结构与首次一致） |
| 同 key + **不同**请求体 | `400`（code 10001）——防止误用旧 key 发新请求 |
| 首次仍在处理中 | `409`（code 10005），请稍后重试 |
| 缺失该头（已注册幂等的接口） | `400`（code 10001） |

**前端建议**：对提交类按钮，进入表单页时生成一个 UUID 作为 key，**提交成功后才丢弃**；
这样网络超时重试是安全的。各接口是否强制幂等，见对应模块文档。

## 7. 错误码表

| code | HTTP | 含义 | 前端建议 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 10000 | 500 | 系统错误 | 提示"服务异常"，附 requestId |
| 10001 | 400 | 参数或业务校验失败 | 直接展示 `message` |
| 10002 | 401 | 未登录 / token 失效 | **跳转登录页** |
| 10003 | 403 | 无权限 | 隐藏入口或提示"无操作权限" |
| 10004 | 404 | 记录不存在 | 提示并回到列表 |
| 10005 | 409 | 幂等冲突 / 状态冲突 | 提示"操作处理中或已提交，请勿重复" |
| 10006 | 423 | 主体已冻结（资质/信用/账号停用） | 提示"账号或主体已被冻结，请联系管理员" |
| 10007 | 429 | 请求过于频繁（登录失败锁定等） | 提示并倒计时后允许重试 |

## 8. 字段剔除（重要）

服务端按角色 `field_mask` **物理删除**敏感字段，被剔除的字段在响应 JSON 里**连 key 都不存在**，
不是 `null`、也不是空串。

- 成本相关字段（`cost` / `margin` / `baseline` 等）对销售、供应商角色一律剔除。
- **前端不要写 `data.cost ?? 0` 这类兜底**，因为该字段根本不存在；需要判断时请用
  `if ('cost' in data)`。
- 同一接口不同角色返回的字段集合可能不同，前端按"字段存在才渲染"处理即可。

## 9. 数据域

服务端已按角色数据域（`SELF` / `DEPT` / `DEPT_SUB` / `ALL`）做了行级过滤，
**前端拿到的列表已经是该用户有权看到的数据**，不需要也不应该再做二次过滤。

## 10. 变更约定

- 接口新增/修改时，后端同步更新本目录文档与 swagger 注解。
- 前端发现文档与实际不符，以本目录文档为准提 bug（文档是契约，实现对不上是实现的问题）。
